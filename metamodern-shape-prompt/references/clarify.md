# Clarify

Return one concise, copy-ready prompt that expresses the user's existing intention precisely. Improve the language without enlarging the task or making the user more certain.

Use the user's words and relevant conversation to locate the central question or desired change. Preserve the situation, audience, constraints, meaningful emotional judgments, and named examples. Use established domain terms only where they preserve a useful distinction.

Do not add deliverables, features, tools, methods, tests, success metrics, deadlines, or implementation decisions the user did not establish. An observed symptom is not a proven cause; an aspiration is not a commitment. Keep “I don't know” when the user does not know.

Return the prompt directly, usually in one to three short paragraphs. Include a brief “Related work” label only when requested or when a domain distinction materially clarifies the task. If one unresolved decision prevents faithful wording, ask about that decision; otherwise preserve the uncertainty inside the prompt.

Completion means the prompt is clearer, still sounds like its author, and contains no unsupported expansion. If an existing prompt already works, retain it.
