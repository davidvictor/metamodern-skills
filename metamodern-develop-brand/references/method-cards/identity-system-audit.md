# Identity system audit

In existing-brand documentation, use this card to describe the current system and its evidence limits. Omit redesign choices and retain/refine/create decisions; distinguish missing documentation from an actual request to change identity. The decision prompts below apply to development or refresh.

## Helps resolve

Which identity elements should remain, change, or be created to make the system coherent and usable.

## Useful when

The brand has recognizable expression but uneven application, incomplete guidance, or a real refresh decision.

## Review first

Editable identity sources, accepted strategy, current applications, production constraints, licenses, and priority contexts.

## Prompt bank

- Which visual elements carry the strongest recognition or meaning?
- Which elements vary without a useful reason?
- How well does the identity express the accepted strategy?
- What breaks when the system moves between website, deck, and document?
- For each relevant element, should we retain, refine, or create?

## Method

Audit each relevant element against the identity principles and priority contexts. Test whether inconsistency is a system gap, an implementation problem, or useful adaptation.

## Synthesis

Record the retain, refine, or create decision for each selected element, with the evidence and constraints behind it.

## Contributes

An identity completion scope and the guidance needed for focused visual development.

## Cautions

Do not audit every possible identity category by default. Preserve editable sources and explore alternatives only when a decision benefits.
