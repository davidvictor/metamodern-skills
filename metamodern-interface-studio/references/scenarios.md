# Scenario and product ownership

Keep four independent stores: product data state, product navigation, Studio selection, and presenter playback. Each mounted preview gets its own data/router/cache/timer/network namespace. Shared immutable fixture bytes are fine; shared mutable stores, service workers, local storage and module singletons require isolation or a declared limitation.

Materialize a scenario from immutable fixture bytes/version/digest, seed, logical clock, environmental conditions, ordered setup commands, and async completion schedule. Inject time, randomness, generated IDs, network results, locale/time zone and relevant environmental inputs through existing application seams. If that cannot be done, narrow the deterministic claim and choose a static fallback where appropriate; do not rewrite product rules in the Studio.

A fingerprint hashes canonical semantic inputs and resulting product state **and navigation**. Sort object keys, preserve meaningful array order, exclude session IDs and wall-clock recording time. Include implementation/source revision and fixture digest. Repeated materialization of identical inputs must yield equal fingerprints and equivalent visible output after the declared readiness barrier. A different fixture or source revision invalidates old evidence even if the screen happens to look the same.

The runtime contract is `materialize(spec) -> isolated session`, `dispatch(command) -> product outcome`, `snapshot()`, `fingerprint()`, `reset()`, and `dispose()`. Dispatch through actual application behavior, including permissions, failure, undo and calculations. Record ordered commands/outcomes when supported, including scheduled completions. The original `scenarioId` remains fixed; set `modified: true` after interaction. Do not classify the current screen backward into a new scenario.

Reset cancels pending work, invalidates old completion epochs, clears preview-local persistence, restores the fixture and initial product navigation, replays setup deterministically, waits for readiness, clears interaction history/modified state and verifies the original fingerprint. Reset during an outstanding request must not let its late response corrupt the restored state. Dispose also cancels listeners, timers, streams and handles. Gallery, Compare and walkthrough runtimes must not mutate the Inspect runtime.

Navigation snapshots describe named outlets: a required primary location and optional detail, overlay and auxiliary locations, each referencing stable surfaces with serializable parameters. Map these to the target's real route tree, tab/stack/modal conventions or panels. Validate representability before applying a snapshot atomically. Deep links, back, dismiss and command-driven navigation need target tests. Studio catalog selection is never a replacement for product navigation.

Fixtures can be synthetic, licensed or otherwise audience-approved. Record origin, version, digest, audience and restrictions in the manifest; use read-only fixture stores or sandboxed writes. Do not connect demonstrations to customer mutation endpoints by default. Shareable URLs contain allowlisted stable selection IDs only. Logs contain semantic event IDs and sanitized outcomes, never raw fixture payloads, credentials or personal values. Resolve assets and fonts under the same audience/licensing boundary.
