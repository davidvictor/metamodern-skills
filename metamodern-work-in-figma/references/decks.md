# Decks and Figma Slides

A deck Project normally has a Figma Design source for foundations, brand assets, reusable Project components, and slide-size recipes, plus a canonical Figma Slides file for narrative order, unique copy, notes, native numbering, motion, and Slides-only objects.

Put repeated patterns such as brand marks, footer shells, dividers, quotes, metrics, profiles, captions, attributions, and image frames in the Design library. Keep each actual slide as a native composition. A reusable shell and a Slides-native object can coexist but must remain separate editable layers.

Use a dedicated Slides starter or team template only when one theme will support many decks. Keep global native numbering by default; covers and section dividers may deliberately omit it. Declare the motion approach in `00 · Overview`, use native Slides motion, and verify it in presentation view.

Keep approved narrative copy and claims tied to their authoritative sources. Comments hold review, questions, and approvals, not hidden system instructions. Use slide groups for narrative sections or presenter ownership rather than temporary work status.

Library publication, subscription, template administration, and some Slides configuration can require UI work. Record the exact action and verify the consumer afterward. Do not assume a PDF or PPTX preserves motion, notes, links, gradients, fonts, or editability.
