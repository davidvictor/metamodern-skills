# Start

Use Start when a project is new or has no incumbent working environment.

## Inspect first

Resolve the intended project root and read the authorized brief, current external records, accepted Brand System, content sources, editable design sources, delivery targets, and existing repository state.

Confirm only material gaps that cannot be answered from current evidence. Do not turn setup into a generic intake interview.

## Create the portable core

Create and fill:

- `PROJECT.md` for the durable project brief.
- `REFERENCES.md` for durable project sources and targets.
- `AGENTS.md` for authority, routing, safeguards, and verification.

Create no empty future artifact. Invoke the owning capability when current work requires `PRODUCT.md`, `BRAND.md`, `DESIGN.md`, or a surface or deliverable brief.

## Establish capability availability

Confirm the required shared Metamodern skills are installed at user scope. Add a project-local skill only when its behavior belongs to the project or subtree. Give it a unique project namespace.

If interface-production setup or implementation is authorized now, follow [Impeccable interface foundation](impeccable-interface-foundation.md) after the portable core is grounded. If no interface is in scope, do not install or initialize Impeccable and do not create `PRODUCT.md` or `DESIGN.md` for possible future work.

## Engineering handoff

For authorized engineering initiation, pass the grounded core, known product/starter choices, authoritative sources, delivery scope, and unresolved dependencies to `metamodern-initiate-engineering`. For MakerKit-only base preparation, use `metamodern-bootstrap-app` directly. Do not repeat supplied decisions. When this is a portable-core-only delegation from either skill, return the core to that caller without dispatching any further setup.

## Verify

Use a fresh-session replay from the project root. Confirm the session can explain the project, locate exact sources and targets, distinguish authority from evidence, choose the correct capability, and identify open decisions.
