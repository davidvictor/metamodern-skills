## Refresh policy

Before every bootstrap run, verify source/license access and the selected ref. For a fresh kit, clone the upstream history into the chosen owned workspace. For continuation, inspect the existing checkout rather than recloning it. Then read the selected checkout's root and applicable nested instructions, remotes, `package.json`, lockfile, workspace and downstream manifests, route/configuration sources, development and test environment consumers, local service configuration, MCP/devtool registrations, and scripts used for a claim. Record the exact ref and date. If a source differs from this table, the selected source wins and this table is only historical inspection evidence. Do not use documentation-only commands as requirements until their presence is demonstrated in the selected release; the inspected generator registry has no `env` generator. Do not invoke `pnpm turbo gen setup` automatically because it can mutate Git configuration, remotes, and hooks.
